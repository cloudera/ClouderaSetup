= Cloudera on-Premises Deployment & Validation on Red Hat OpenShift Virtualization

== 1. Executive Summary

As enterprises modernize their on-premises data infrastructure, the combination of Cloudera Data Platform and Red Hat OpenShift Virtualization (OCP-V) is emerging as a transformative architecture.

This joint engineering work demonstrates:

* Production-grade deployment of Cloudera on-premises Base (a.k.a Cloudera Private Cloud Base) on OCP-V
* Successful validation at 100+ OCP-V Virtualized nodes
* End-to-end integration with Data Services (CDW, CDE, CAI)
* Enterprise-grade security with TLS, Kerberos, LDAP, Ranger, and Knox
* A real end-to-end Bank Branch Performance Analytics use case spanning ingestion → processing → visualization

This single document integrates all deployment steps, architecture, validation reports, and outcomes—serving as a reference blueprint for field, engineering, and customer teams.

== 2. Why OpenShift Virtualization for Cloudera?

=== 2.1 Challenges with Traditional Bare Metal / Legacy Hypervisors

Organizations using legacy VM platforms or bare-metal servers face:

* Static & rigid resource allocation
* Complex lifecycle management and patching
* Slow infra provisioning
* Hardware-dependent scaling
* Split operational models (VMs vs containers)

These issues slow down the rollout of large analytics clusters like Cloudera Platform.

=== 2.2 Benefits of Deploying Cloudera on OCP-V

OpenShift Virtualization brings cloud-native virtualization onto Kubernetes, offering:

[cols="1,3",options="header"]
|===
| Benefit | Description
| Unified Platform | Run containers + VMs on one K8s platform
| Elastic Scaling | CPU/Memory/Disk tuned dynamically across workers
| Rapid Provisioning | VM templates, GitOps, CI/CD-driven lifecycle
| High Availability | OpenShift operators, MachineSets, self-healing
| Cost Efficiency | Significantly higher node utilization
| Security & Compliance | RBAC, SCC, NetworkPolicies, Encryption
| Automation | GitOps + Ansible + CM API automation for infra and Cloudera
|===

This makes OCP-V an ideal substrate for Cloudera’s on-prem analytics platform.

== 3. Architecture Overview

The validated architecture consists of:

=== Platform Layer (OCP-V)

* OpenShift 4.x deployed on bare-metal worker nodes
* OpenShift Virtualization Operator enabled
* Worker nodes configured for VM scheduling and live migration
* VM networks via Multus, VLAN bridging
* Storage via OpenShift Data Foundation (ODF)
* Node-Local Storage via the Local Storage Operator (LSO)

=== Virtual Machines

Cloudera Base services run entirely inside OCP-V VMs:

* Cloudera Manager Node
* Utility/Database Node (PostgreSQL)
* Master Nodes (NameNode, Hive Metastore, ResourceManager, etc.)
* Worker Nodes (DataNode, NodeManager, Impala, Kafka brokers, HBase RegionServers, etc.)
* NiFi & NiFi Registry
* FreeIPA (for Kerberos)
* Ranger, Knox, Atlas, Solr, Ozone, Spark3, Tez, Phoenix, Iceberg, Hive, Impala

All VM nodes were RHEL 9.5 with Cloudera-certified stacks.

=== Data Services Layer (Optional on Bare-Metal or OCP-V VMs)

* CDE: Spark 3.5.1 Clusters, Pipelines, Jobs
* CDW: Hive & Impala Virtual Warehouses, Data Catalog, Viz
* CAI: Workspaces, AMP deployments, Agent Studio deployment, GPU/CPU workloads

Hybrid topologies were validated (Base on OCP-V + Data Services on Bare Metal).

== 4. OpenShift Virtualization Deployment

=== 4.1 OpenShift Cluster Setup

* OpenShift 4.x deployed using IPI/UPI
* Multiple worker nodes with virtualization enabled (KubeVirt)
* OpenShift Virtualization Operator installation
* Validation of CPU virtualization extensions (VT-x/AMD-V)

=== 4.2 Storage & Networking

* ODF configured for VM disks (RWX PVCs to support Live Migration)
* Multus network bridging for VM L2/L3 connectivity
* VM interfaces exposed via Linux Bridge / SR-IOV as needed

=== 4.3 VM Templates & Cloud-Init

VM provisioning automated using:

* RHEL-9.5 base template
* Cloud-init for:
** Hostname & network configs
** SSH keys
** Subscription & package installations
** Disk configuration
** Cloudera prerequisites
